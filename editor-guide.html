Часть I. Основы

1. Введение: что вы создаёте

Вы создаёте проект игры — набор сцен, персонажей, предметов и квестов, который движок показывает игроку как интерактивную историю. Сцена — это место действия: текст, кнопки-выборы, иногда диалог или бой. Квест — цепочка задач в журнале («поговорить», «найти», «победить»). Всё это хранится в одном файле данных проекта и редактируется через формы в editor.html.

Редактор рассчитан на авторов и мастеров игры, а не на программистов. Вы называете локации понятными словами, пишете текст для игрока, связываете сцены выборами и настраиваете награды. Движок сам ведёт журнал квестов, инвентарь и бой — вам не нужно писать код.

По умолчанию включён Writer Mode (кнопка ✏️ Writer Mode в шапке). В нём видны разделы для сюжета: сцены, квесты, персонажи, предметы, мир. Режим ⚙️ Advanced Mode добавляет классы, умения, крафт, вкладку 📦 Данные и тонкую настройку правил. Переключение режима не меняет ваш проект — только набор вкладок.

Три источника помощи работают вместе: это руководство, подсказки ? у полей в формах и короткий интерактивный туториал при первом запуске редактора (шесть шагов от сцены до сохранения). Если поле кажется непонятным — нажмите ? рядом с подписью: там объяснение именно для этого поля.

Минимум для игры: одна стартовая сцена с текстом, хотя бы один выбор с переходом и сохранённый JSON. Всё остальное наращивается по мере роста кампании.
Подсказки в редакторе: обложка проекта — project-cover; название места на сцене — scene-location.

2. Обновления движка (с первой версии руководства)

Интерфейс редактора заметно изменился. Если вы читали старое руководство или смотрели чужие скриншоты — ориентируйтесь на список ниже. Подробности по темам разбросаны по следующим главам этого документа.

  • Навигация по задачам — разделы сгруппированы: Создание, Контент, Инструменты, Расширенные. Сцены, Сюжет, квесты и NPC открываются из боковой панели разделов.
  • Writer Mode / Advanced Mode — переключатель в шапке; технические вкладки скрыты в режиме писателя.
  • Стартовая сцена — на панели проекта блок 🎬 Стартовая сцена: явно задаётся, с какой сцены начнётся игра после экспорта. Проверяется валидатором.
  • Карта истории — в сайдбаре сцен переключатель Текст / Карта. На карте: обзор связей, чеклист структуры (сироты, битые ссылки, достижимость), клик по предупреждению ведёт к сцене; клик по переходу позволяет сменить цель.
  • Единый валидатор — кнопка 🔍 Проверить проект и панель ошибок внизу окна. Клик по проблеме открывает нужную сущность (сцена, квест, NPC).
  • Условия на понятном языке — в выборах и сценах конструктор правил для «Показать если» / «Скрыть если» без обязательного редактирования кода (поля choice-show-if, choice-hide-if).
  • Рабочее пространство сцен — несколько сцен можно держать открытыми вкладками; переключение не помечает проект «грязным», если вы только смотрите.
  • Модули сцены — сцена собирается блоками через + Добавить: «Текст и локация», «Выборы», диалог, NPC, квест и др.
  • Шаблоны сцен и стартовые проекты — при 📄 Новый проект можно выбрать Blank, Text, Visual или Village вместо пустого файла.
  • Мастера сценариев — на панели сцены кнопки вроде 📜 Старт квеста помогают привязать квест к выбору без ручной возни.
  • Палитра команд Ctrl+K — быстрый поиск: создать сцену, квест, сохранить, проверить, открыть карту истории.
  • Автосохранение черновика — статус ● Несохранённые изменения / ✓ Сохранено в шапке; при сбое браузера можно восстановить черновик (это не замена экспорта JSON).
  • Превью и Play — справа вид «глазами игрока»; кнопка Play открывает игру с текущими данными.
  • Дашборд — 🏠 Дашборд и клик по заголовку MythMill: сводка проекта, обложка, подсказки по проверке.
Формулировка «вам не нужны флаги и условия» устарела. Для обычных квестов через мастер и задачи журнала ручные флаги чаще не нужны. Но скрытые кнопки, ветвления и «состояние» сцены — это отдельные поля редактора; о них — в главах про выборы и условия.

3. Файлы и поток данных

У проекта три «адреса» в файловой системе. editor.html — рабочее место автора. index.html — игра для игрока (открывается после экспорта или через Play в редакторе). game_data.json (или любое имя с вашими данными) — сердце проекта: сцены, квесты, NPC, предметы, настройки обложки и стартовая сцена.

Типичный цикл: 📂 Загрузить JSON → правки в формах → 💾 Сохранить проект → пункт Сохранить в JSON. Этот файл — ваш основной архив: его можно копировать, отправлять соавтору, снова открывать в редакторе. Экспорт в HTML или в папку нужен, когда история готова к публикации; обратно в редактор такой HTML не загружается.

Пока вы работаете, редактор периодически пишет черновик в браузер (автосохранение). В шапке видно, есть ли несохранённые изменения относительно последнего экспорта. Если вкладку закрыли аварийно, при следующем открытии может появиться предложение восстановить черновик — согласуйте его с файлом на диске.

Внутри JSON нет отдельной «карты сюжета» как второй базы: связи между сценами — это поля to у выборов и nextScene у сцен. Карта в редакторе только показывает и помогает править эти же поля.

Вкладка 📦 Данные (Advanced Mode) показывает сырой JSON для просмотра. Правки там не сохраняются автоматически — основной путь через формы.
Подсказка: предпросмотр JSON — json-preview. Туториал: шаг «Сохранение» — меню 💾 Сохранить проект, пункт Сохранить в JSON.

4. Запуск редактора и игры

Откройте editor.html в Chrome, Edge или Firefox на компьютере (ширина от 768px). На приветственном экране два пути: 📄 Создать новый проект или 📂 Загрузить game_data.json для уже существующей работы.

При создании проекта выберите шаблон: Blank RPG — одна пустая сцена; Text — задел под текстовую кампанию; Visual — сцена с визуальным слоем; Village — готовая демо-деревня с квестом «Пропавшие припасы» для изучения. После создания откроется редактор сцен.

Задайте 🎬 Стартовая сцена на панели проекта (дашборд или блок метаданных): это сцена, с которой игрок начнёт после создания персонажа и при экспорте HTML. Если поле пустое, движок попытается угадать сцену start или первую в списке — лучше указать явно. Первая созданная вами сцена в пустом проекте часто назначается стартовой автоматически.

Проверьте игру до долгой работы: откройте сцену, посмотрите превью справа и нажмите Play — откроется index.html с текущими данными. Вернуться к правкам можно в любой момент; Play не заменяет сохранение JSON.

🏠 Дашборд (кнопка в шапке или клик по названию MythMill) показывает статистику, обложку и краткие напоминания о проверке проекта.

Подсказки: обложка — project-cover; куда ведёт выбор — choice-to; локация — scene-location. Туториал: шаги «Создайте сцену», «Превью и Play», «Сохранение».

5. Интерфейс редактора

Окно редактора делится на зоны. Шапка — проект, загрузка и сохранение, 🔍 Проверить проект, ссылка 📖 Руководство, переключатель Writer / Advanced. Под шапкой — панель разделов (Сцены, Сюжет, Квесты, Предметы, Персонажи и т.д.) с группировкой по задачам.

Боковая панель слева (в разделе Сцены) — список сцен, поиск, кнопка + Новая сцена и переключатель Текст / Карта. В режиме Текст в центре — редактор выбранной сцены: модули добавляются кнопкой + Добавить («Текст и локация», «Выборы», диалог, NPC…). В режиме Карта на том же месте — карта истории: слои сцен, переходы, чеклист структуры и список проблем с переходом к сцене по клику.

Справа (если включено превью) — вид сцены глазами игрока и кнопка Play. При редактировании текста превью обновляется по мере ввода.

Раздел Сюжет (вкладка с картой) — альтернативный вид связей: «Карта истории» (нарратив) и «Редактор связей» (граф переходов). Для ежедневной работы удобнее Текст / Карта прямо в списке сцен.

Ctrl+K открывает палитру команд: создать сцену, квест, NPC, сохранить, проверить проект, открыть карту истории, переключить режим. У многих полей форм есть иконка ? — краткая справка по полю (тот же текст, что в справочнике подсказок редактора).

Несколько сцен можно держать открытыми вкладками в рабочей области: переключение между ними не требует сохранения. Статус ● Несохранённые изменения появляется, когда вы реально меняете данные проекта.

Подсказки: текст сцены — scene-text; подпись кнопки — choice-text; переход — choice-to; квест на выборе — choice-quest-set. Туториал: шаги «Текст сцены», «Выбор», «Квест на выборе», «Превью и Play».

Часть II. Создание игры

6. Создание игры с нуля: пошаговый план

Ниже — порядок работ для кампании от идеи до тестируемого прототипа. Это не замена туториалу, а карта на несколько сессий.

  1. Проект и старт. Создайте проект (шаблон Blank или Text). Назначьте 🎬 Стартовую сцену. Напишите вступительную локацию: текст + один выбор «дальше».
  2. Каркас локаций. Добавьте хаб (деревня, база) и 2–3 сцены-ветки. Связывайте выборами (choice-to). Включите режим Карта и проверьте чеклист: нет ли сирот и битых ссылок.
  3. NPC и предметы. В разделах Персонажи и Предметы создайте имена до квестов — так в мастере квеста будут готовые списки для выбора.
  4. Квесты. Вкладка Квесты → мастер создания или карточка квеста: этапы, задачи (поговорить, собрать, посетить…), награда. Привяжите старт к сцене через 📜 Старт квеста или «Продвинуть квест» в карточке выбора.
  5. Диалоги и ветки. В сценах добавьте реплики и выборы с разными переходами. Для сложных веток используйте «Показать если» / «Скрыть если» — конструктор правил, без обязательного кода.
  6. Проверка. 🔍 Проверить проект — исправьте ошибки по списку (клик ведёт к полю). На карте истории — предупреждения о недостижимых сценах.
  7. Сохранение и тест. Сохранить в JSON, затем Play и полный проход с журналом квестов.

О квестах и «технике». Задачи квеста (поговорить, доставить, победить) сами отслеживают прогресс в журнале — отдельные флаги для этого обычно не нужны. Поле «Продвинуть квест» на выборе меняет этап без ручной записи переменных. Если же кнопка должна появиться только после события — это условия видимости и иногда «состояние» сцены; они доступны в расширенных полях выбора и в Advanced Mode.

Нельзя сохранить задачу «Поговорить» без выбранного NPC — валидатор остановит ошибку. Сначала создайте персонажа, потом квест.
Подсказки: название квеста — quest-title; награда золотом — quest-reward-gold; имя NPC — npc-name; предмет — item-name.

7. Мастер-класс: первая сцена за 15 минут

Повторите шаги интерактивного туториала редактора на чистом шаблоне Blank RPG. Если туториал уже предлагался при открытии — можно пройти его снова через настройки или просто следовать списку ниже.

  1. Новый проект. 📄 Новый проект → шаблон Blank RPG → подтвердите создание.
  2. Сцена. В сайдбаре + Новая сцена, введите название места (например, «Старый мост»). Внутренний ID создастся сам.
  3. Текст. В редакторе сцены + Добавить → Текст и локация. Напишите 2–3 предложения, что видит игрок. Справа проверьте превью.
  4. Выбор. + Добавить → модуль выборов. Создайте кнопку с текстом («Осмотреть берег») и укажите целевую сцену — можно вторую новую сцену или ту же для проверки.
  5. Квест (по желанию). В карточке выбора включите продвижение квеста или нажмите 📜 Старт квеста на панели сцены, создайте простой квест с одним этапом.
  6. Play. Нажмите Play, пройдите сцену в открывшейся вкладке, убедитесь, что текст и кнопка работают.
  7. Сохранение. 💾 Сохранить проект → Сохранить в JSON. Файл на диске — ваша точка возврата.

Готово: у вас минимальный вертикальный срез — сцена, текст, переход, сохранённый проект. Дальше расширяйте по плану из раздела 6: NPC, квест с задачами, проверка проекта. Для примера готовой деревни с квестом откройте шаблон Village при создании проекта и изучите сцены «Деревня» и квест «Пропавшие припасы».

Туториал в редакторе (6 шагов): создать сцену → текст → выбор → квест на выборе → Play → сохранить JSON. Номера совпадают с шагами выше.
Подсказки по полям этого мастер-класса: scene-location, scene-text, choice-text, choice-to, choice-quest-set.

8. Структура game_data.json

Файл проекта — один JSON-объект. В корне лежат разделы, которые вы наполняете через вкладки редактора. Главные для автора сюжета: scenes (сцены), quests (квесты), npcs, items, enemies. Поле startScene (или meta.startScene) указывает, с какой сцены начнётся игра.

Блок meta хранит название кампании, автора, версию, систему правил (meta.system: generic, dnd5e, pf2e) и обложку. Технические разделы — classes, progression, theme, audio, worldMap — нужны, если вы настраиваете бой, уровни и интерфейс. Пустые объекты вроде startingFlags: {} — нормальны для нового проекта.

Каждая сцена в scenes — объект с полями location, text, массивом choices и опциональными модулями (бой, диалог, флаги при входе). Квесты в формате v2: stages → tasks с типами вроде TalkToNPC, CollectItem. Редактор при сохранении не создаёт «вторую копию» данных — карта истории и валидатор читают те же поля.

Имена сцен и квестов в JSON — латиница без пробелов (ID). Игрок видит Локацию и название квеста из отдельных полей.
Подсказки: scene-id, quest-id, npc-id, json-preview.

9. Вкладка «Данные» (JSON)

Вкладка 📦 Данные доступна в Advanced Mode (группа «Расширенные» → «Данные»). На ней блок Данные проекта показывает весь JSON в виде текста — только для чтения и резервной копии.

Подсказка под заголовком прямо говорит: обычная работа — через формы слева, без правки этого текста. Превью обновляется при изменениях в редакторе (updateJSONPreview), но вставить правку в окно и «сохранить» нельзя — для этого есть экспорт JSON из меню 💾 Сохранить проект.

Когда JSON полезен: передать файл соавтору, сравнить две версии внешним diff-ом, найти редкое поле, которого нет в форме. Для квестов в режиме разработчика есть отдельный quest-json-preview на карточке квеста — он тоже для просмотра, не для ручного редактирования в Writer Mode.

В Writer Mode вкладка «Данные» скрыта намеренно — чтобы не отвлекать от форм.
Подсказка: json-preview.

10. Метаданные проекта

Метаданные описывают кампанию целиком, а не отдельную сцену. Откройте 🏠 Дашборд или панель проекта: там видны Название, Версия, Автор и Система правил. Кнопка ✏️ Мета открывает редактирование полей meta.title, описания и автора.

Ниже на той же панели — 🎬 Стартовая сцена (выбор из списка сцен) и блок 🖼 Обложка: загрузка PNG/JPG до 500 КБ, показ на главном экране игры. Кнопки 📷 Загрузить обложку и зона перетаскивания файла работают сразу после открытия проекта.

Стартовая сцена обязательна для предсказуемого экспорта: валидатор предупредит, если указана несуществующая сцена или если из старта недостижимы другие локации. Назначение старта не заменяет связи выборов — игрок всё равно попадает на сцены только по переходам из геймплея.

Подсказки: project-cover; стартовая сцена — entity-picker сцен на панели проекта.

11. Системы правил (D&D 5e / Pathfinder 2e)

При 📄 Новый проект в модальном окне есть поле Система правил — выпадающий список (#editor-new-project-system). Выбор задаёт meta.system и влияет на создание персонажа, рас, классов и боевые формулы. Основные варианты: generic (упрощённая система), dnd5e, pf2e (Pathfinder 2e).

Для D&D 5e стартовый проект может включить прогрессию уровней, таблицу опыта и масштабирование врагов. Для PF2e — отдельные расы-ancestries, heritage, бусты характеристик и свои подписи в редакторе рас. Систему нельзя «переключить незаметно» без последствий: смена лучше делать на новом проекте или после проверки совместимости контента.

На дашборде и панели проекта система показывается человекочитаемым именем (через getRuleSystemLabel). В игре движок подключает соответствующий модуль (например, Pathfinder2eSystem для pf2e). Если вы пишете только текстовую историю без боя — подойдёт generic.

Шаблоны Blank / Text / Visual / Village при создании проекта задают свой набор сцен; систему правил можно выбрать отдельно в том же окне.

Часть III. Сцены и нарратив

12. Сцены: поля и модули

Сцена собирается из модулей — блоков, которые вы добавляете кнопкой + Добавить в редакторе. Базовые для большинства историй: Текст и локация, Выборы, NPC, Диалог. Дополнительные: Бой, Предметы (выдача при входе), Звук, Хаб / возврат, Карта (точка на карте путешествий), Магазин, Кузница, Церковь и др.

В шапке карточки сцены: ID сцены (латиница, для переходов) и Локация — название для игрока. Основной текст — в модуле «Текст и локация»; подстановки {charName} и сниппеты @id поддерживаются. Модуль Бой: список врагов и поле Сцена после победы — куда отправить игрока после победы.

Модуль Хаб / возврат добавляет кнопку возврата на площадь (scene-returns-to-hub, scene-hub-scene). Модуль Флаги — установка значений при входе в сцену (см. раздел 17). Не добавляйте модули «на будущее»: пустой модуль только загромождает форму.

Режим Карта в сайдбаре не меняет структуру сцены — он показывает те же переходы и позволяет переназначить цель кликом по ребру.

Подсказки: scene-id, scene-location, scene-text, scene-npc-id, scene-enemies, scene-next-scene, scene-items, scene-gold, scene-audio, scene-special. Туториал: шаги «Создайте сцену», «Текст сцены».

13. Состояния локации

Одна и та же сцена может выглядеть по-разному в зависимости от прогресса — например, храм «до ритуала» и «после». Для этого у сцены есть массив states (состояния локации). В редакторе блок 🔄 Состояния локации (states) с кнопкой + Добавить появляется, когда модуль состояний подключён к сцене.

У каждого состояния — свой id, условие (когда оно активно), и переопределения: текст, локация, звук, выборы, специальный тип. Одно состояние можно пометить как по умолчанию. Условия состояний опираются на флаги и прогресс — это продвинутая механика; для простых квестов чаще хватает отдельных сцен или условий на кнопках.

Внутри состояния можно задать собственные выборы — отдельно от основного списка сцены. Порядок состояний меняется кнопками вверх/вниз. Перед публикацией проверьте проект: «мёртвое» состояние без выполнимого условия может скрыть весь контент сцены.

Состояния локации — не путать с этапами квеста. Этапы квеста настраиваются во вкладке Квесты; состояния — только для вида одной сцены.

14. Выборы: переход, проверка навыка, действие

Выбор — кнопка внизу экрана у игрока. Добавляется модулем Выборы или мастерами сцены. У каждой карточки выбора: подпись (текст кнопки), иконка, поле Тип и цель.

Переход — обычная смена сцены: укажите целевую сцену в поле перехода (choice-to). Проверка навыка — бросок d20: навык, сложность DC, сцены или действия при успехе и провале (choice-skill, choice-skill-success, choice-skill-fail). Действие — вызов зарегистрированного action из вкладки Действия (Advanced); вместо перехода выполняется скрипт движка (choice-action).

Опция «один раз» (doneFlag) скрывает кнопку после использования, если настроены условия choiceUsed / hideIf. Для Writer Mode лишние технические поля свёрнуты — включите Advanced или раскройте блок навыка, если нужны флаги при успехе проверки.

Подсказки: choice-text, choice-icon, choice-type, choice-to, choice-action, choice-done-flag. Туториал: шаг «Выбор (кнопка)».

15. Конструктор условий (showIf / hideIf)

Блоки Показать если и Скрыть если в карточке выбора управляют видимостью кнопки. В Writer Mode открывается конструктор на понятном языке: правила вроде «у игрока есть предмет», «этап квеста равен…», «репутация с фракцией…», «выбор уже использован». Кнопка + Добавить условие добавляет правило; несколько правил объединяются «и» / «или».

Поддерживаемые типы включают: предмет в инвентаре / нет предмета, золото от/до, этап квеста, класс персонажа, использованный выбор, репутация, флаг / не флаг. Текст правила показывается фразой на русском; под капотом сохраняется структура для движка. В Advanced Mode можно переключиться на ручной JSON/JavaScript — это для опытных авторов.

Те же идеи применяются к точкам на карте мира и другим полям с условием видимости. Перед публикацией используйте превью выборов или Play: условие, которое никогда не выполнится, спрячет кнопку навсегда.

Подсказки: choice-show-if, choice-hide-if, condition-appearance, world-map-condition.

16. Смена этапа квеста на выборе (questSet)

Чтобы сюжет двигался без ручных флагов, привяжите квест к выбору. В карточке выбора — блок Продвинуть квест / «квест при выборе» (choice-quest-set): выберите квест и этап из списков с человеческими названиями. При нажатии кнопки игрок перейдёт на сцену и журнал квеста обновится до выбранной стадии.

Быстрый путь — мастер 📜 Старт квеста на панели сцены (openScenarioWizard('quest')): он создаёт выбор с уже привязанным квестом. Альтернатива — мастер 📜 Мастер: старт / этап квеста в наборе сценариев. Оба пишут в те же поля questSet, что и ручная форма.

Этапы нумеруются так, как в карточке квеста во вкладке Квесты. Если квест удалён, валидатор и карта истории покажут предупреждение «квест не найден». Для завершения квеста используйте этап с типом завершения или задачу «После нажатия «Продолжить»» на финальном этапе — не отдельный флаг вручную.

Подсказки: choice-quest-set, quest-stage-type. Туториал: шаг «Квест на выборе».

Часть IV. Персонажи и бой

17. Флаги и память игры

Флаги — именованные значения «да/нет» или числа, которые движок запоминает между сценами. Они нужны для ветвлений сложнее, чем журнал квестов: «дверь уже открыта», «игрок видел секрет». Это не замена квестов — для заданий «поговорить / собрать» используйте задачи квеста.

Установить флаги можно модулем 🚩 Флаги на сцене (при входе), при успешной проверке навыка, в расширенных настройках выбора (doneFlag — «кнопка уже нажата»). Стартовые значения — в startingFlags проекта; каталог переменных — вкладка Переменные (Writer Mode), кнопка + Новая переменная.

В конструкторе условий флаг фигурирует как правило «состояние» / «флаг» (flag, notFlag). В интерфейсе Writer Mode поле может называться «состояние» вместо жаргона «флаг» — смысл тот же. Условие choiceUsed отслеживает нажатие конкретной кнопки без отдельного имени флага.

Для типичного квеста «найти и принести» флаги не обязательны: прогресс ведёт QuestRuntime по задачам этапа.
Подсказки: choice-done-flag, choice-show-if (тип flag).

18. Система квестов

Квест — цепочка этапов, в каждом — одна или несколько задач. Игрок видит название, подсказку этапа и прогресс в журнале. Создание: вкладка Квесты → Мастер… или + новый квест. Мастер спрашивает «Что должен сделать игрок?» — поговорить, найти, собрать, доставить, победить, посетить место, смешанный вариант или свой пустой квест.

В карточке квеста: название для игрока, этапы с полями «Название этапа», «Подсказка в журнале», кнопка + Добавить задачу. Типы задач в обычном списке: Поговорить, Собрать / найти предмет, Победить врага, Доставить предмет, Посетить место, Потратить золото, После нажатия «Продолжить» и др. — экспериментальные типы в Writer Mode скрыты. Задачу «Поговорить» нельзя сохранить без выбранного NPC.

Награда — блок золота, опыта и предметов на карточке квеста (quest-reward-gold, quest-reward-exp, quest-reward-items). Этапы перетаскиваются за ☰. Старт квеста в сюжете — через questSet на выборе или мастер на сцене. 🔍 Проверить проект подсветит битые ссылки на NPC, предметы и сцены.

Подсказки: quest-title, quest-hidden, quest-stage-hint, quest-stage-log, quest-faction, quest-reputation. Туториал: шаг «Квест на выборе»; полный цикл — раздел 6.

19. Классы персонажа

Раздел Классы — в Advanced Mode (группа «Расширенные»). Здесь шаблоны героев: название, иконка, стартовое оружие и предметы, базовые характеристики, ресурс класса (мана, ярость…). Список классов слева; клик открывает карточку справа.

Умения не пишутся целиком внутри класса: они берутся из общего пула вкладки Умения (progression.abilities). Класс хранит ссылки на id умений; кнопка ✨ Мастер умения помогает создать новое. Прогрессия уровней — отдельная вкладка Прогрессия (progression-enabled, таблица опыта, кость HP).

Для сюжетной RPG без тактического боя классы можно не трогать: игрок создаётся с упрощёнными статами. Если включена система dnd5e или pf2e, классы должны соответствовать выбранной системе правил. Сцена «создание персонажа» подключается шаблоном сцены или специальным типом (scene-special).

Подсказки: class-id, class-resource, class-main-weapon, class-starting-items, class-stats.

20. Расы и наследия (ancestries)

Вкладка Расы (Advanced) — расы D&D 5e и ancestries Pathfinder 2e. Кнопка + Добавить расу создаёт запись; в карточке поле Система: D&D 5e или Pathfinder 2e. От системы зависят поля: для PF2e — ability boosts, ОЗ ancestry, список heritages (наследий); для D&D — бонусы характеристик и черты.

У каждой расы — имя, иконка, описание. Наследия PF2e добавляются кнопкой в блоке heritage; у каждого своё имя и модификаторы. Расы выбираются при создании персонажа в игре, если в проекте настроен экран создания героя. Метка [PF2e] в списке слева помогает отличить ancestry от классической расы.

Не смешивайте в одном проекте несовместимые наборы без необходимости: система правил в meta.system должна соответствовать большинству рас. Для чисто нарративной игры на generic достаточно одной-двух условных «рас» с flavor-текстом или можно обойтись без вкладки вовсе.

Подсказки: поля рас в форме редактора; шаблон сцены character_creation — модуль «Создание персонажа».

21. Создание персонажа в игре

Игрок может собрать героя до начала кампании — имя, раса, класс, характеристики, предыстория. В редакторе это два уровня: шаблоны героев во вкладке Герой (player_characters) и сцена создания персонажа в сюжете (тип character_creation, модуль в шаблонах сцен).

Вкладка Герой (раздел Персонажи → Герой): список заготовок, кнопка создания, поля имени, портрета, расы, класса, текста предыстории и стартового инвентаря. Режимы «быстрый» и «подробный» переключают глубину формы. Эти записи попадают в playerCharacters JSON — удобно для фиксированного протагониста или тестового героя.

Для выбора в самой игре добавьте сцену с типом Создание персонажа или special character_creation и поставьте её в цепочку до стартовой локации (или сделайте стартовой). Игрок пройдёт мастер в рантайме; данные сохранятся в слот персонажа. Расы и классы должны быть заранее созданы во вкладках Расы и Классы.

Подсказки: class-stats, class-starting-items; валидация имени героя — при пустом имени редактор покажет ошибку.

22. Умения и эффекты

Вкладка Умения (Advanced) — общий каталог способностей progression.abilities. Каждое умение: название, иконка, описание, тип (активное / пассивное), стоимость ресурса, формула урона или лечения, тип урона, дальность, область, спасбросок цели.

Типы эффектов в форме: урон, лечение, бафф, статус, дополнительная атака, магический снаряд, кара и др. Кнопка ✨ Мастер умения на панели классов помогает собрать типовое умение. Классы ссылаются на умения по id из пула, а не хранят копии — одно умение можно выдать нескольким классам.

Для сюжетной игры без тактического боя вкладку можно не трогать: достаточно проверок навыка на выборах. Умения нужны, если в проекте включён бой с панелью действий и ресурсами класса (ячейки, ярость).

Подсказки: ability-name, ability-formula, ability-cost, ability-damage-type, ability-save, ability-passive.

23. Каталог умений «Мельница на Тихой реке»

Демо-кампания Мельница на Тихой реке (D&D и PF2e варианты) — эталонный набор умений, классов и боя. Откройте соответствующий демо-проект или загрузите data/game_data.json / demo-pf2e.js и изучите вкладку Умения и назначения в Классах.

В каталоге демо видно, как оформлены: урон костями (1d8+mod), лечение, баффы брони, реакции «при атаке», пассивные бонусы HP. Это образец для своих способностей — копируйте структуру через дублирование в редакторе, не выдумывая поля с нуля. Названия и иконки в демо на русском; id остаётся латиницей.

Демо не связано с шаблоном Village: это отдельная кампания про мельника и деревню Горнистead. Для обучения боевке загрузите демо, для квестов без боя — шаблон Village из раздела 4.

24. Прогрессия и уровни (1–10, ASI)

Вкладка Прогрессия (Advanced, часто рядом с классами): включение системы уровней, максимальный уровень, таблица порогов опыта, кость прироста HP (1d8, 1d10…), опыт за врагов и проверки навыков по умолчанию.

Поля progression-enabled, progression-max-level, progression-exp-table соответствуют подсказкам «?» в форме. При повышении уровня в игре движок начисляет HP и (в системах D&D/PF2e) может предложить улучшение характеристик (ASI) — логика зависит от meta.system.

Задачи квеста Достичь уровня читают уровень из сохранения игрока. Если прогрессия выключена, уровень остаётся фиксированным — такие задачи не имеют смысла. Для короткой истории оставьте maxLevel: 5 и простую таблицу опыта из стартового шаблона D&D.

Подсказки: progression-enabled, progression-exp-table, progression-hp-gain.

25. Предметы и экипировка

Вкладка Предметы: список слева, карточка справа, кнопка + Новый предмет. Поля: название, тип (оружие, броня, расходник, аксессуар…), описание, иконка, урон и характеристика для оружия, бонус КД для брони, эффект расходника (лечение, урон), кнопка использования.

Предметы выбираются в квестах («собрать», «доставить»), выдаются модулем Предметы на сцене, настраиваются как добыча у врагов и стартовая экипировка класса. Блок Добавить бонус — пассивные JSON-бонусы для аксессуаров. Не дублируйте один предмет под разными id — квесты ссылаются на id.

Условие «есть предмет» в конструкторе выборов использует тот же id из каталога. После переименования предмета id не меняется (это ключ в JSON); меняется только отображаемое имя.

Подсказки: item-name, item-type, item-dmg, item-ac, item-effect, item-use-label, item-bonuses.

26. Боевая система

Бой запускается модулем Бой на сцене: список врагов из вкладки Враги и обязательное поле Сцена после победы (scene-next-scene). Без него после победы экран может зависнуть — валидатор и подсказка «?» предупреждают об этом.

В бою игрок и враги ходят по правилам активной системы (meta.system): броски атаки, урон, КД, инициатива. Умения с вкладки Умения появляются на панели, если назначены классу. Проверки навыка вне боя — отдельный тип выбора «Проверка навыка», не полноценный бой.

Масштабирование сложности — вкладка Баланс (enemyScaling): множители HP и урона врагов по уровню игрока. Для нарративной игры бой можно не использовать вовсе — только текстовые сцены и квесты.

Подсказки: scene-enemies, scene-next-scene, balance-enemy-scaling.

27. Враги, бой, масштабирование

Вкладка Враги (раздел «Враги»): карточка с именем, HP, КД, атакой, формулой урона, ловкостью, опытом за победу. Блок Добыча (loot): предмет, шанс 0–1, min/max количества — кнопка + Добавить предмет.

Врага выбирают в модуле боя сцены и в задаче квеста «Победить врага». Id врага — латиница; имя видит игрок в бою. Вкладка Баланс показывает таблицу enemyScaling и отчёт: как меняются статы при росте уровня героя. Сброс таблицы возвращает значения по умолчанию движка.

Не создавайте десятки почти одинаковых врагов — лучше один id и масштабирование, или варианты с разным loot. Проверьте проект: ссылка на несуществующего врага в квесте или сцене попадёт в список ошибок валидатора.

Подсказки: enemy-hp, enemy-ac, enemy-atk, enemy-dmg, loot-chance.

28. Справочник NPC

Вкладка Персонажи → NPC: список, Добавить NPC, поля имя (обязательно для валидации), иконка/портрет, описание, локация (для автора), базовое отношение (дружелюбный, нейтральный, враждебный).

NPC выбираются в задаче квеста «Поговорить», в поле NPC сцены (scene-npc-id — репутация при разговоре), в диалогах и мастерах сцен. Создайте NPC до квестов, которые на них ссылаются. Имя в списке — то, что увидит игрок в журнале и репликах; внутренний id остаётся техническим ключом.

Отдельно от NPC — вкладка Герой для играбельных персонажей (playerCharacters). Не путайте: NPC — для мира и квестов «поговорить», герой — протагонист игрока.

Подсказки: npc-name, npc-desc, npc-attitude, scene-npc-id.

29. Компонентные сцены и цепочки действий

Модуль Компоненты UI на сцене добавляет интерактивные блоки: диалог-дерево, торговля, цепочки действий без ручного JSON. Модули Магазин, Кузница, Церковь выставляют scene.special (shop, blacksmith, temple) и готовые компоненты.

Вкладка Действия (Advanced) — реестр именованных action для выбора типа «Действие» (choice-action). Visual-сцены и UI-hotspots (Phase G) добавляют переходы visual_* и scene_enter — они видны на карте истории как дополнительные рёбра.

Модуль Элементы сцены — последовательные блоки (текст, звук, задержка) для кинематографичных сцен. Для типичной текстовой RPG хватит «Текст + Выборы»; компоненты подключайте, когда нужен магазин, ветвящийся диалог или визуальный клик по карте.

Подсказки: scene-special, choice-action, action-registry-id.

Часть V. Расширение движка

30. Карта путешествий

Вкладка Мир → Карта путешествий редактирует worldMap: точки с подписью, иконкой, целевой сценой и условием видимости. На сцене модуль Карта или поле Точка на карте путешествий привязывает локацию к точке; кнопка + Создать из сцены добавляет запись в каталог.

Игрок в игре открывает меню «Переместиться» и видит открытые точки. Первый визит в сцену с mapLocation может открыть точку на карте. Hub-сцена — быстрый возврат на площадь (связано с модулем Хаб / возврат). Условие видимости точки — тот же конструктор правил, что у выборов.

Подсказки: world-map-point, world-map-condition, scene-hub-scene.

31. Карта сюжета

Два входа к одним данным: переключатель Текст / Карта в сайдбаре сцен (режим «Карта») и вкладка Сюжет с подрежимами Карта истории и Редактор связей. Карта строится из choices.to и nextScene — отдельной базы графа в JSON нет.

На Карте истории: слои по «шагам» от старта, карточки сцен, клик по переходу — сменить целевую сцену (entity-picker), чеклист структуры (старт, сироты, битые ссылки, хаб→финал), кликабельные предупреждения с переходом к сцене в списке. Режим запоминается для текущего проекта, не глобально.

Редактор связей — схема Mermaid/граф для обзора всех переходов; удобен на больших кампаниях. После правки на карте проверьте JSON-превью или 🔍 Проверить проект — изменения сразу в данных сцены.

См. также раздел 2 (обновления карты истории).

32. Аудио

Вкладка Звук (группа «Ассеты»): каталог audio.catalog — id, подпись, путь к MP3 относительно корня (audio/...). На сцене модуль Звук или поля ambient/SFX выбирают id из каталога (scene-audio).

У умения — поля звука применения и попадания (audio-sfx-cast, audio-sfx-hit). Файлы кладите в папку audio/ проекта; при экспорте в папку они должны попасть в сборку. Без файла в каталоге выбор в форме будет пустым или с предупреждением при тесте.

Подсказки: audio-catalog-id, audio-catalog-file, audio-catalog-label.

33. Тема интерфейса

Вкладка Тема (Advanced → Ассеты): пресеты («пергамент», тёмная и др.) и кастомные цвета — фон страницы, бумага, акцент, текст. Изменения пишутся в data.theme и применяются к игре при экспорте; на дашборде есть превью палитры.

Тема не меняет тексты сюжета — только оформление кнопок, журнала, инвентаря. После смены пресета нажмите Play и убедитесь, что контраст читаемый. Обложка проекта (meta.cover) — отдельно от темы UI.

34. Интерфейс игрока

Вкладка Игровой UI (game_ui, Writer Mode): экраны HUD, журнал, инвентарь, меню — визуальный конструктор слоёв поверх игры. Экраны типов hud, journal, inventory, pause и др.; виджеты вроде кнопки журнала, трекера квестов.

Для текстовой RPG достаточно стандартного HUD движка. Кастомный UI нужен, если вы делаете visual-новеллу с собственными кнопками или overlay-сценами. Связь с данными: hotspots visual-сцены могут вызывать ui_show и открывать экран из этого раздела.

Превью справа в редакторе сцен показывает текст и выборы, но не всегда полный HUD — для проверки UI используйте Play.

35. Проверка проекта

🔍 Проверить проект в шапке (и в палитре Ctrl+K) запускает единый валидатор. Результат — панель Ошибки внизу окна: счётчики, список проблем, клик по строке открывает сцену, квест, NPC или поле (navigateToValidationIssue).

Типичные ошибки: битый переход на сцену, квест «Поговорить» без NPC, несуществующий startScene, недостижимые сцены, пустая «сцена после победы». Кнопка Исправить всё, что возможно автоматически (если показана) чинит только безопасные случаи — например, добавить пустой этап квеста; битые ссылки на NPC вы правите сами.

Карта истории дублирует часть проверок (сироты, битые ссылки) в чеклисте под картой — удобно во время написания; перед экспортом всё равно прогоните полную проверку.

Туториал: после первых сцен имеет смысл проверить проект перед сохранением.

36. Сохранение и экспорт

💾 Сохранить проект ▾ — три формата. Сохранить в JSON — рабочий файл для редактора (основной архив). Экспортировать в HTML — один файл игры для публикации, обратно в редактор не загружается. Экспорт в папку — index.html + ресурсы (Chrome / Edge).

Автосохранение в браузере и статус ● Несохранённые изменения — страховка, не замена JSON на диске. Перед релизом: JSON + тест HTML-сборки. Экспорт может блокироваться, если валидатор нашёл критические ошибки (Phase H) — сначала исправьте список.

Ctrl+K → «Сохранить» / «Экспортировать» дублируют меню. После экспорта JSON обложка сбрасывает кэш — актуальная картинка попадёт в следующий экспорт игры.

Туториал: финальный шаг — Сохранить в JSON.

37. Частые ошибки и FAQ

Игра начинается не с той сцены. Проверьте 🎬 Стартовую сцену на панели проекта и что эта сцена существует.

Кнопка выбора не появляется. Смотрите «Показать если» / «Скрыть если» и превью видимости в карточке выбора; условие может быть ложным при тесте.

Квест не продвигается. Убедитесь, что задача соответствует действию (поговорили с тем NPC, собрали предмет), и что на выборе настроен questSet или задача автоматически засчитывается движком.

Чёрный экран после боя. Заполните Сцену после победы в модуле боя.

«Вам не нужны флаги» — правда? Для квестов через мастер — да, прогресс ведёт журнал. Флаги и условия нужны для скрытых кнопок, состояний локации и веток вне квестов.

Редактор на телефоне. Экран < 768px показывает заглушку; авторство — только на ПК. Играть можно на телефоне.

38. Чеклист перед релизом

  1. Стартовая сцена назначена и существует.
  2. 🔍 Проверить проект — ноль ошибок (предупреждения разобраны).
  3. Карта истории (режим Карта): чеклист зелёный или осознанные жёлтые пункты; нет битых ссылок.
  4. Пройти игру Play от старта до финала основной ветки; журнал квестов обновляется.
  5. NPC и предметы в квестах существуют; имена NPC заполнены.
  6. Бои имеют сцену после победы.
  7. Сохранить в JSON на диск; при публикации — экспорт HTML или папки и повторный тест сборки.
  8. Обложка и мета (название, автор) заполнены для игрока.

40. Plugin API для special-сцен (наследие и расширения)

Поле Специальный тип сцены (scene.special) переключает поведение движка: магазин, отдых, создание персонажа, кастомные режимы. Встроенные типы регистрирует SpecialSceneRegistry (файл special-scenes.js).

Автору без программирования достаточно модулей Магазин, Кузница, Церковь и типа Создание персонажа — они выставляют special автоматически. Если указать неизвестный special, игра покажет предупреждение и откроет сцену как обычную текстовую.

Расширение для разработчиков: SpecialSceneRegistry.register(id, label, handler) или массив plugins.specialScenes в JSON. Это не требуется для типичной кампании в Writer Mode. Подробности — Developer Guide.

Подсказка: scene-special.

41. Создание своих систем правил

Из коробки зарегистрированы generic, dnd5e, pf2e (SystemRegistry). Выбор при создании проекта задаёт meta.system и влияет на бой, расу, прогрессию и создание героя.

Добавить четвёртую систему «без кода» в интерфейсе нельзя: нужен JS-модуль с объектом системы и вызов SystemRegistry.register, плюс согласованные классы, расы и таблицы. Для авторов историй рекомендуется generic или dnd5e с готовыми шаблонами.

Сменить систему у готового проекта рискованно: id рас, классов и формулы боя могут перестать совпадать. Безопаснее новый проект с нужной системой и перенос сцен/квестов вручную. Метка системы на дашборде и в ✏️ Мета — только для справки и экспорта.
